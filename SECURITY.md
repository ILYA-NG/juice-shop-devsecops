# DevSecOps Pipeline для OWASP Juice Shop

## 1. Цель проекта

Создать безопасный CI/CD-пайплайн для open-source приложения OWASP Juice Shop с автоматическими проверками безопасности на всех этапах разработки и Security Gateway для блокировки небезопасных релизов.

## 2. Архитектура пайплайна

Пайплайн реализован на GitHub Actions и запускается автоматически:
- при push в ветку `main`;
- при создании pull request в ветку `main`.

### Этапы пайплайна

1. **Secret Scanning (Gitleaks)** — поиск секретов в репозитории.
2. **SAST (Semgrep)** — статический анализ кода.
3. **Dependency Scan (Trivy FS)** — проверка зависимостей.
4. **Container Scan (Trivy Image)** — сканирование Docker-образа.
5. **DAST (OWASP ZAP)** — динамическое сканирование запущенного приложения.
6. **Security Gateway** — блокировка релиза при наличии CRITICAL/HIGH уязвимостей.
7. **Comment on PR** — автоматический комментарий в pull request при блокировке.

## 3. Используемые инструменты

| Этап | Инструмент | Назначение |
|---|---|---|
| Secrets | Gitleaks | Поиск секретов в коде |
| SAST | Semgrep | Статический анализ кода |
| SCA | Trivy FS | Проверка зависимостей |
| Container | Trivy Image | Скан Docker-образа |
| DAST | OWASP ZAP | Динамическое сканирование |
| Gateway | GitHub Actions | Блокировка при CRITICAL/HIGH |

## 5. Security Gateway

### 5.1. Триггер на остановку релиза

- **Условие:** блокировка merge/deploy при наличии CRITICAL или HIGH уязвимостей.
- **Срабатывание:** Gateway заблокировал релиз из-за 46 уязвимостей (10 Critical + 36 High), найденных Trivy в образе Juice Shop.
- **Результат:** job `gateway` завершён с ошибкой, релиз заблокирован.

### 5.2. Дополнительные триггеры

- **Комментарий в PR:** бот `github-actions[bot]` автоматически оставил комментарий в pull request о блокировке релиза.
- **Рекомендации по исправлению:**
  - Обновить уязвимые зависимости в образе Juice Shop.
  - Следовать рекомендациям Trivy по устранению CVE.
  - Устранить уязвимости, найденные ZAP (5 Medium, 5 Low).

## 6. Выводы

- Пайплайн покрывает все этапы DevSecOps: CI/CD, SAST, DAST, Security Checks, Security Gateway.
- Security Gateway эффективно блокирует небезопасные релизы при наличии CRITICAL/HIGH уязвимостей.
- Все результаты сканирования выгружаются в GitHub Security (SARIF) и артефакты (ZAP HTML-отчёт).
- Зоны роста: интеграция с SIEM, автоматическое создание тикетов в системе менеджмента уязвимостей, расширение набора правил сканирования.
